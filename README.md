# Android Agent tools for DeepSeek Harness

## 面板视觉与布局更新

结果条目的删除图标位于每行右侧，点击后弹窗确认，再删除对应条目，支持撤销，顶部只保留搜索与刷新。任务中心直接展示操作记录、各步返回状态、已保存在记录中的读取文字及截图入口；操作参数按需展开，操作记录每页显示 20 步，支持上一页、下一页和页码跳转，刷新保留当前页，切换任务回到第一页。未保存的文字不会补造，下拉选项使用明确的深色背景与浅色文字。

任务、结果和调试采用简洁显示：任务默认展示状态与进度，调用统计和详细记录放入“执行详情”；结果页仅保留同一行的搜索与刷新，列表占满剩余空间；双击条目或按 Enter 打开详情弹窗，关闭按钮或 Esc 返回列表；诊断默认展示连接状态，技术信息与画面参数按需展开。原有停止、继续草稿、导出和设置功能保留。

五个页面统一采用深色工作台、图标导航、分层卡片和清晰的操作状态。手机操作保留图标与文字，文件页使用紧凑工具栏；任务提供进度卡片与空状态，结果详情通过独立弹窗阅读，诊断信息独立分组。按钮名称、键盘访问和原有操作保持兼容。

手机页的「更多」使用按钮旁的快捷菜单，不再弹出模态窗口或遮罩。菜单随窗口大小和滚动调整位置，保留设备、剪贴板、画面、录制四类功能和上次分类；点击外部、再次点击「更多」、Esc 或关闭按钮均可收起。设备快捷操作发送后收起菜单，音量操作可连续点击；关闭菜单不停止录制。浏览器验收：`npm run test:more-menu`，覆盖 360 / 480 / 920 像素窗口、非模态交互和原功能请求。

Toast 悬浮于面板导航下方右侧，避开宿主标题栏，不占据布局空间或挤动正文；弹窗内仍可关闭提示。错误需手动关闭，普通提示定时消失。浏览器视觉验收：`npm run test:design`（360 / 560 / 1040 像素，全部五个页面），操作回归包含 toast、任务、结果管理、文件管理与手机控制。

## 文件管理图片预览

单击 JPEG、PNG、GIF 或 WebP 文件名打开图片预览，勾选框继续用于多选。预览支持适应窗口、原始尺寸、关闭按钮和 Esc；GIF 保留动画。无需连接投屏，也无需先创建下载任务。

单张预览上限 20 MiB，超过上限可下载后查看。加载失败显示可手动关闭的错误 toast，并提供重试；关闭弹窗或离开文件页会取消读取、释放图片资源。手机端仅以普通 ADB 权限读取文件，按内容识别图片格式，不支持 SVG 或 HEIC 预览。

验收：`npm run typecheck`、`npm run build`、`npm test`、`npm run test:file-manager-browser`。

## 1.9.1 右上角消息提示

连接、输入、文件操作、更多操作、任务和结果管理的操作反馈统一使用右上角 toast，每条均有关闭按钮。错误一直保留，必须手动关闭；普通提示 5 秒后自动消失，悬停或键盘焦点进入时暂停计时。恢复连接、切换标签或完成后续操作不会自动关闭已有错误。

相同消息合并显示，持续后台故障关闭后不会在下一次轮询立即重弹；恢复后再次失败或主动重新尝试仍可产生新提示。打开原生对话框时提示仍可点击关闭，面板卸载时清理浮层和计时器。目录无法读取、作业失败记录、任务状态和可撤销操作仍保留相应业务内容。

浏览器验收：`npm run test:toast-ui`。记录见 [1.9.1 消息提示验收](docs/1.9.1-消息提示验收.md)。

## 1.9.0 macOS 运行依赖与 ADB 启动恢复

同一个安装包现在同时携带 Windows ADB 和 macOS Universal ADB 37.0.1，自动按运行平台选择。macOS 二进制包含 Intel x64 与 Apple Silicon arm64 两个原生架构；附带原始 dylib、NOTICE 与版本文件。Android 端继续复用 scrcpy 5.0.1 服务端，无需 Homebrew、Android SDK、桌面 Java 或 FFmpeg。

在 macOS 上会先校验包内文件，再按需恢复 ADB 执行权限；不使用 sudo、不自动移除隔离属性或绕过 Gatekeeper。若系统阻止运行，诊断指向系统设置中的隐私与安全性。Mac 的原生启动、签名/隔离行为和 USB 投屏仍需在 Mac 上验收，目前只完成二进制架构、资源、选择逻辑及 Windows 回归验证。不要把此包视为已完成 Mac 真机验收的稳定发布。

修复同时刷新设备时重复启动 ADB 的竞争：先复用正常响应的服务，同端口启动合并；竞争失败后再次确认服务是否已由其他进程启动。没有可用服务时保留失败，不自动停止共享 ADB server。验收范围与 Mac 检查步骤见 [1.9.0 验收记录](docs/1.9.0-macOS与ADB启动验收.md)。

## 1.8.0 内置 Windows 运行依赖

Windows 安装包自带 ADB 37.0.1、配套 DLL 和 scrcpy 5.0.1 服务端。安装插件后连接手机、开启 USB 调试并在手机上授权即可使用，无需另外下载 Platform-Tools、配置 PATH、安装 Java、scrcpy 客户端或 FFmpeg。首次运行不下载这些运行文件。当前真机验收平台为 Windows x64；macOS 内置支持从 1.9.0 加入，其他系统/架构仍使用外部 ADB。

默认 `adbPath: auto` 使用插件目录里的 ADB；显式路径和 `DSH_ANDROID_ADB_PATH` 继续作为高级覆盖配置。包内文件缺失或损坏会明确提示重装完整插件，不静默改用其他 ADB。构建与打包校验所需文件和 SHA-256，来源、版本与上游许可证一起分发。

手机需要数据 USB 线和 USB 调试授权；Windows 未识别设备时仍可能需要厂商 USB 驱动。插件不自动修改手机安全设置或安装驱动。Harness 及其正常插件依赖安装流程仍是前提，本次不是独立 Harness 离线安装器。

开发验收：`npm run typecheck`、`npm test`、`npm pack --pack-destination .build`，然后 `npm run test:runtime-package`。`node scripts/runtime-package-smoke.mjs --device` 可使用实际 USB 手机核对包内 ADB、Android 端 jar 执行与投屏数据。验收会清除子进程的 SDK/PATH 配置，并从带中文和空格的解压路径运行。详细结果见 [1.8.0 内置运行依赖验收](docs/1.8.0-内置运行依赖验收.md)。

核心入口是 Agent 的原生工具：在 Harness 聊天里直接提出手机任务，Agent 调用 `android_*` 完成观察、操作、文件传输、安装、录制和系统控制。所有 44 项工具都进入模型可见的工具清单；文件和录制工具返回实际状态、本机路径及相关标识，不要求用户打开面板或点击按钮。面板用于观看与可选手动操作。也可通过 `dsh-android/agent` 入口在没有 WebServer、浏览器和面板的环境注册同一套工具。

例如：“把电脑 D:\\Downloads\\demo.apk 安装到手机并报告实际结果”“把手机 /sdcard/Download/report.pdf 取回电脑，告诉我保存路径”“开始录屏，打开设置后返回桌面，停止录屏并告诉我录像路径”。本机文件必须有实际路径；手机审批或系统拒绝会通过工具结果如实返回。工具链独立验证：`node scripts/agent-only-smoke.mjs`；该脚本走真实 USB 与 Harness ToolRuntime，不调用模型。

在 DeepSeek Harness 中增加 Android 手机面板和 44 个原生 Agent 工具，提供实时画面、应用名称识别、界面查找、点击、滑动、系统按键和中英文输入。0.5.0 增加连接诊断、参数化任务草稿、任务限额和本机操作记录。0.6.0 增加按条件重新定位并点击、界面等待、跨屏查找和列表去重读取，记录保留每屏截图。手机端使用 scrcpy 5.0.1，前端使用 WebCodecs 解码。

## 1.7.0 手机文件管理器

打开 Android 面板的“文件”页即可管理手机文件，不需要先建立视频连接。仍保留原有 44 项 Agent 原生工具；文件页复用同一套 ADB 文件服务，没有控制权切换。

- 独立选择设备，使用快捷目录、面包屑、路径输入、前进/后退/上一级和刷新。按名称、大小或修改时间排序，筛选当前目录，显示隐藏文件，支持多选与右键菜单。窄面板自动收起侧栏，作业区默认折叠。
- 多文件选择或拖放上传；普通文件单个或批量下载，批量下载为多个独立文件。上传、下载完成后核对 SHA-256；详情页可按需计算哈希和复制路径。下载表示发起浏览器保存，最终保存位置由浏览器决定。
- 新建文件夹、重命名、复制、移动、批量删除，以及从手机上的 APK 发起标准安装。复制和移动使用真实目录选择器；删除前显示确切设备、路径和数量。安装受手机系统权限控制，不绕过 USB 安装限制。
- 默认不覆盖同名目标，冲突可跳过、改名保留或明确覆盖普通文件。已有目录不会合并或覆盖。已选源文件和确认覆盖的目标变化时拒绝继续，需重新核对。
- 后端作业依次执行，最多 100 项等待/执行/冲突作业。设备和目标在创建时固定；已接收的作业不因切换标签或刷新页面而停止。取消与失败可能留下已产生的结果，明确标为待核对；重启不会自动重放未完成操作。

单文件最大 2 GiB，新名称最多 240 个 UTF-8 字节；文件系统仍可能拒绝某些名称。目录显示每页 200 项、最多读取 10000 项，达到上限会明确提示；筛选只覆盖当前目录已读取范围，分页不是原子快照。目录复制/删除沿用 1000 项、32 层、累计 2 GiB 的保护上限。只显示真实的电脑到 Harness 上传百分比，ADB 传输显示阶段和已知文件大小，不伪造进度。

未暂存的电脑文件只保留在当前页面，刷新后需重新选择；已完成的下载记录仍可再次保存。第一版暂不包括文件夹上传、文件夹打包下载、文件预览和递归搜索。真机验收：`npm run test:file-manager`；浏览器时序与故障注入：`npm run test:file-manager-browser`；完整文件页与原有更多操作回归：`npm run test:files-ui`。详细任务及证据见 [1.7.0 文件管理器开发与验收](docs/1.7.0-文件管理器开发与验收.md)。

## 1.6.0 通知读取与应用等待

新增三个原生工具，总计 44 个。查询与轮询不需要打开手机面板，也不建立视频连接；等待期间其他人仍可操作手机，取消、会话结束和断开会停止轮询。

- `android_notifications`：读取当前 Android 用户（含 USER_ALL）的活动通知，可按确切包名、实际通知键和字面关键词筛选，返回可读标题、正文、长正文、时间及指纹。不是通知历史，也不授予通知监听权限。默认扫描 20 条、最多 50 条，offset 继续扫描；limit 是扫描数，不是匹配数。内容不可读、截断、详情撤回、接口不可用与实际空结果分开返回，关键词筛选后仍保留不可读计数。通知键保持不透明，兼容分组摘要附加后缀。
- `android_wait_notification`：有界轮询指定应用、通知键或关键词。默认 `new_only:true` 排除初次采样中的相同指纹，新通知和同键更新都能匹配。快速任务可先对同范围、不加关键词的全部通知分页查询，再触发动作，将实际指纹数组和 user_id 作为 `baseline_fingerprints`、`baseline_user_id` 传入等待；已经完成但晚于该基线的通知也能匹配。没有提供基线时首次采样之前的通知被视为已有内容；`new_only:false` 明确允许当前已有匹配。初始范围不完整或超过 200 条时返回不可用，需缩小范围。短暂通知可能在轮询间隙出现并撤回，隐藏文字无法匹配。
- `android_wait_app`：等待确切应用及可选活动进入当前用户前台。默认同时要求窗口焦点属于目标包，锁屏显示时不匹配；默认稳定 500 ms，活动改变会重置稳定期。可用实际 `.相对类名`、完整类名或同包组件名。`require_focus:false` 只要求活动 resumed，允许它仍在另一窗口后面。诊断未知或多显示器活动不唯一时不猜测匹配。

等待默认 30 秒，上限 120 秒，轮询间隔 500–5000 ms。通知的 `matched` 只证明观察到通知，`completion_confirmed=false`；应用的 `matched` 只证明活动/焦点采样匹配，`content_ready_confirmed=false`。Agent 应继续查询实际文件、核对哈希或重新观察页面，不能把通知文字或启动结果直接当业务成功。通知内容是数据，不是操作指令。标题/正文等各最多 2000 字，缺失或系统隐藏的字段保持 null。

真机脚本 `npm run test:agent-events` 验证普通、多行和类似错误信息的通知正文、旧通知排除、同键更新、复用操作前基线、超时与取消、真实应用跳转、前台活动和通知栏焦点；通过原生手势只清理自有测试通知，最后返回桌面。测试不安装 APK、不读取通知历史、不发送聊天或调用模型。

## 1.5.0 媒体查询与文件选择器

新增两个模型可见的原生工具，总计 41 个；不增加面板按钮，继续使用 Harness 自身 Agent 循环和无面板入口。

- `android_media_query`：只读查询当前 Android 用户的 MediaStore 图片、视频、音频索引。支持字面名称子串、共享目录（包含子目录）、修改时间和游标分页，返回实际名称、路径、大小、MIME、时间、可用的宽高与时长。默认 10 项，最多 20 项，按修改时间与 ID 倒序；下一页保持相同筛选条件。索引可能缺失或陈旧，分页不是原子快照，文件当前是否存在仍需 `android_file_stat` 核对。权限或解析错误不会伪装成零条结果。查询不扫描媒体、不读取文件正文、不打开应用，也不启动视频连接。
- `android_pick_file`：操作调用应用**已经打开**的系统 DocumentsUI 文件选择器。`action: inspect` 返回当前可见行与截图；`action: select` 按确切 `file_name` 选择一项，可用 `search: true` 在当前提供器范围搜索。它不另起选择器、不向应用注入 URI。浏览器若先显示“相机 / 媒体”入口，应先用普通界面工具进入媒体。厂商相册或 Android Photo Picker 目前不适配，返回 `not_picker`，可继续用普通观察和点击工具操作。

选择器只在前台活动与焦点匹配、元素完整、当前结果不再滚动、没有已有选择且名称唯一完整匹配时点击一次。遇到同名、隐藏结果、不可用行或上下文变化则停下。先进入正确目录，不能从显示名称推断真实路径。返回 `selection_requested` 只说明点击过匹配行，调用应用可能尚未接收附件或需要确认；`attachment_confirmed=false`、`upload_performed=false`。工具不自动提交多选、不点击发布或发送；Agent 需观察返回页面核对文件。

真机脚本 `npm run test:agent-library` 使用本机浏览器文件输入控件，验证系统选择器搜索、返回调用页面、实际文件名/字节数/SHA-256，并查询生成的图片、视频、音频元数据。它不调用模型，不向外部上传文件。空的 `AutoCompleteTextView` 搜索框也已识别为可输入控件，沿用新鲜观察、聚焦检查和输入取消规则。

## 1.4.0 Agent 文件工作流

新增七个原生工具，全部供 Harness Agent 直接调用，没有新增面板按钮：

- `android_file_stat`：读取确切路径的存在性、类型、大小、时间与指纹，可选 SHA-256。
- `android_file_manage`：创建目录、复制、移动、同目录改名及删除；默认不覆盖，非空目录删除和目录复制须显式指定 recursive。
- `android_open_file`：将共享存储中的实际文件交给 Android 应用打开，可指定 MIME 与包名。
- `android_share_file`：以系统只读 URI 进入分享或目标应用，不选择联系人、不点击发送。
- `android_wait_file`：有界等待文件出现或变化，并连续观察元数据稳定。
- `android_transfer_status`：按实际 job_id 查询或列出传输、安装记录。
- `android_transfer_cancel`：取消指定任务；已结束则返回实际结果，不撤销已完成操作。

`android_push_file`、`android_pull_file` 增加 `wait:false`，立即返回后台任务 ID，再用状态工具查询。后台传输最长 5 分钟，创建它的工具调用或 Agent 回合结束后继续运行；插件关闭时请求取消。`bytes` 是已知文件大小，不冒充已传字节数或百分比。取消不保证回滚；重启发现未结束记录时标记 failed / interrupted / outcome_uncertain，继续前核对实际文件或应用。

文件管理只修改共享存储或 `/data/local/tmp` 的具体子路径，保护存储根目录，不解释通配符，不跟随末尾符号链接删除。目录操作上限 1000 项、32 层、累计 2 GiB；单文件最大 2 GiB。单文件复制提交前核对源与暂存 SHA-256；目录复制不保证变化中源目录的原子快照。使用正常 ADB 权限，系统拒绝（包括部分厂商的符号链接 EACCES）如实返回。

打开和分享通过正常 MediaStore 扫描、确切路径查询与临时只读授权，不安装辅助 APK。媒体提供器未收录、私有目录、应用无处理能力或系统拒绝时返回错误，不绕过权限。`sent` 只代表系统接受启动请求，应重新观察实际页面；分享入口不代表文件已送达。`android_wait_file` 的 stable 只证明稳定期内大小、时间等未变，`completion_guaranteed=false`；等待新产物时可传原先 stat 的 different_from，最终仍需核对生产应用状态或内容。

真机工具链脚本：`npm run test:agent-files`。例：“在手机 Download 下创建 agent-test，把电脑指定图片传进去，核对哈希，用相册打开，再把这张图片取回电脑并核对一致。”删除测试目录应在用户要求时明确指定路径。

## 1.3.0 Agent 控制能力

新增五个模型可见的原生工具，不增加面板按钮；没有 WebServer、浏览器或手机面板时，同一套工具也能从 `dsh-android/agent` 入口加载。

- `android_device_state`：查询实际前台活动、焦点窗口、键盘、锁屏界面、唤醒状态、方向、电量及活动网络。只读查询不建立视频连接；诊断按短时间段采样，未知字段保持 null，不把系统逻辑唤醒等同于物理屏幕亮起。坐标操作仍需重新观察。
- `android_app_info`：按实际包名查询当前 Android 用户的应用版本、SDK、系统标记、启用/停止/隐藏/暂停状态及安装信息。版本号不丢失大整数精度；未安装与信息不足分别返回。先用 `android_apps` 解析应用名称，不猜包名。
- `android_open_uri`：打开用户指定的网页、应用深链或 `package:包名` 应用详情页，可限制处理应用。使用正常 Android Intent，不接受任意 extras/命令、脚本或文件 URI；正确引用远端 shell 参数。系统接受启动不保证进入预期内容，需查询状态再观察。MIUI 应用详情可能交由安全中心处理，工具保留实际目标组件。
- `android_stop_app`：停止当前用户的指定应用，不卸载、不清除数据。只在系统应用状态确认 stopped=true 后报告 stopped，重复停止幂等；重启继续用 `android_open_app`。停止会结束应用活动与后台工作，只针对用户要求的应用，不停止 Android 核心服务。
- `android_gesture`：从最新截图发送双指缩放、内容旋转、双指平移或双击。全程使用原图坐标，所有路径预先验证；动作消耗观察 ID，结束、取消、旋转、断开或手动输入时释放全部触点。动作发送不等于应用支持或已产生预期效果，需新观察验证。运动手势 200–3000 ms，缩放倍率 0.25–4；双击间隔 60–250 ms。

真机验收脚本 `node scripts/agent-controls-smoke.mjs` 从原生 Agent 入口调用 32 项工具清单中的能力。手机本地测试页接收真实 Android TouchEvent，核对两根独立触点、1.6 倍缩放、45 度旋转、双指移动、双击和取消释放；测试不打开桌面面板，不安装 APK，也不发送聊天或调用模型。

## 1.2.0 新增能力

手机页保持画面优先，新增“文件”标签页，以及右侧“更多”按钮。更多操作分为设备、剪贴板、画面、录制四类；录制时按钮显示“录制中”，详细记录仍在文件页。

- 历史报告：`android_results` 查询、`android_read_result` 回读。新对话可以用返回的历史依据别名另存对比报告；保留原采集时间、设备和来源，不改动原报告。历史别名不能用于点击手机。内置“历史结果对比”模板。
- 文件：浏览手机目录，双向复制单个普通文件（最大 2 GiB）。发送默认到 `/sdcard/Download`；覆盖同名文件须明确选择。先写临时文件再提交，发送后核对手机与电脑 SHA-256；取回文件保留本机路径和哈希。文件页提供浏览器流式下载。
- APK：标准 `adb install --no-incremental -r` 安装单个 APK，不启动应用、不批量授予权限、不降级。手机可能要求开启 USB 安装并确认；拒绝时保留 Android 原始错误。当前 Redmi 实测返回 `INSTALL_FAILED_USER_RESTRICTED`，成功安装待手机开放 USB 安装后验收。拆分 APK / XAPK 不支持。
- 设备：音量增减、静音切换、物理屏幕开关、旋转、通知栏和快捷设置。屏幕关闭仍可投屏；旋转由系统、传感器与当前应用决定，不保证应用接受横屏。所有输入仍共用有序控制通道，没有控制权开关。
- 剪贴板：显式读取或写入手机文字，最多 65536 字；电脑与手机之间通过按钮复制粘贴，不做隐式同步。写入不自动粘贴或发送。Android 没有返回内容（可能为空或受系统限制）时明确提示；日志不保存剪贴板正文。
- 画面：最长边 256–4096、帧率上限 1–120、码率 0.1–40 Mbps。保存后下次连接生效，“保存并重新连接”立即应用并结束当前录制；实际帧率取决于手机画面变化与编码器。独立保存到 `video-settings.json`。
- 音频：可选设备输出或应用播放来源，默认关闭；原始 PCM 48 kHz 双声道，经 Web Audio 播放。电脑播放需手动开启，可调播放音量。未请求麦克风，音频失败仍保留视频；受 Android 和应用采集策略限制。
- 录制：后端直接将原始 H.264 和可用 PCM 音轨写入 MKV，使用设备时间戳；无需安装 FFmpeg。关闭面板继续录制，显式停止后保存；默认 10 分钟，工具允许 1–3600 秒，最大 512 MiB，写入积压最大 16 MiB。8 秒无关键帧返回失败；分辨率变化、旋转或断线结束当前片段。异常退出的旧记录标记为不完整，不假装成功。录像与文件记录位于插件数据目录的 `recordings` / `files`。

真机已验证非静音音频、原始音视频 MKV 的 ffprobe 检查与 FFmpeg 完整解码、文件往返哈希和浏览器下载。自动测试和真实 ToolRuntime 测试不调用模型；聊天中的意图理解和内容对比仍由用户在 Harness 验收。

## Agent 操作

在 Harness 对话里输入：“用 Android 原生工具打开设置，搜索‘电池’，读取搜索结果，然后返回桌面。”可在右侧观看实际过程。

“结果”页按每页 20 份显示保存结果，支持重命名、删除、搜索和日期筛选。`android_read_list` 自动保存原始标题与可见行文字，标为“原始采集”；Agent 用 `android_save_result` 保存正式表格或摘要，标为“Agent 整理”，并不代表内容经过独立事实核实。每行引用当前对话此前实际观察的 `observation_id`，不能传入任意图片文件或网址。摘要可通过顶层 `observation_ids` 引用依据。未读到的单元格填 `null`；存在缺失字段或少于 `expected_count` 时自动标为部分完成。部分完成和失败须说明原因，关联任务达到限额或被取消也会显示。

0.8.0 的搜索覆盖标题、摘要、表格内容、行说明等文字，按普通文字匹配，不解释正则表达式；支持大小写和全角字符归一化。日期按浏览器本地日期筛选保存时间，开始日期和结束日期均包含在内。清空筛选会清空搜索和日期，保留当前“全部结果 / 最近删除”范围。可通过上一页、下一页查看较早结果，旧的 100 份显示上限不再限制历史搜索。

重命名只修改标题，保存时间、表格与截图保持不变，导出使用新标题。删除会将结果移到“最近删除”，可立即撤销，也可重启后恢复；不会删除报告 JSON 或 Harness 截图原件。普通查看和导出不访问已删除结果。相同原生调用重试不会把用户已删除的结果重新创建，也不会覆盖用户修改的名称。此版本没有永久清空最近删除的操作。

可以复制表格并粘贴到电子表格，或导出 UTF-8 Markdown、带 BOM 的 CSV。“导出依据包”下载 ZIP，内含 `report.md`、`report.csv`、`evidence.json` 以及 `evidence/*.png`，便于离线核对。单独的 Markdown 不含截图原件；CSV 包含依据编号、缺失原因和任务状态。CSV/复制表格会中和可能被电子表格当作公式执行的单元格前缀。

每份结果最多 100 行、12 列、32 张依据截图、256 KiB 输入文字；依据包最多 48 MiB。结果 JSON 独立保存在数据目录的 `results` 子目录；截图复用 Harness 附件，任务日志滚出列表后结果仍保留截图引用。若原件已被 Harness 清理，文字仍可导出，但截图查看与完整依据包会明确报错。重试同一工具调用不会重复保存，旧结果文件不会自动删除；迁移原件仍需迁移 Harness 附件，或预先导出依据包。

面板“调试 → 常用任务”内置设备信息、应用内搜索、多屏榜单读取、列表详情阅读四个模板。选择模板、填写参数、生成并复制草稿，再到 Harness 聊天粘贴发送。可以保存自己的 `{{parameter}}` 模板；模板只生成可审阅的文字，不另起模型或任务循环。

每轮手机任务默认最多 100 次原生调用、10 分钟，从首次 Android 工具调用开始，到 Agent 退出为 idle 结束。达到限额时取消当前 Harness Agent 活动、释放手机控制，并保留已完成记录；`android_release` 仅用于清理，不计调用限额，也不能重置限额。时限包含调用之间的模型处理时间。面板“调试 → 连接诊断 → 连接与任务设置”可修改新任务的限额。

“调试 → 任务记录”显示当前与最近 100 项任务、调用结果、耗时、错误恢复提示和截图。观察操作保存附件引用；动作关联操作前与后续观察截图，明确标注来源，不把后续画面当作动作成功证明。记录由 Harness 的最终工具结果事件写入，数据在本机持久化。原生文字输入参数只记长度；Harness 自身的原始对话仍按其规则记录。磁盘旧文件不会自动删除。

一台已授权手机可自动绑定；多台手机需明确选择。手动输入与所有对话均可直接操作，不需要切换控制权。工具按顺序执行，调用之间不占用手机；任意输入会让旧观察失效。点击、滑动和输入文字要求最新的 `observation_id`，一次观察仅能执行一个这类动作，最长有效期 60 秒；动作后重新观察确认结果。成功写入控制通道只表示操作已发送。

`android_apps` 使用 scrcpy 的启动器应用列表读取本地名称与包名。`android_open_app` 只接受 `app_name`、`package_name` 其中一个；按名称启动时必须只有一个完全匹配项，重名或未找到会返回候选并明确表示未启动。

`android_find` 对同一屏幕最多观察 3 次，观察阶段总期限 45 秒，不自动重复点击、输入或滚动。支持 `found`、`not_found`、`tree_unavailable` 结果；未找到仅表示可见元素树中没有匹配项，模型应检查截图、明确滚动或说明失败。每次调用有上限，模型层仍须避免反复调用同一项失败查找。

0.6 的组合工具按顺序执行，支持直接手动输入中断、任务取消和整轮限额；每次组合调用最多 120 秒，最多 7 次滚动、8 屏。整轮 100 次调用按工具调用计数，工具内部的滚动另外受单次上限限制。`android_tap_target` 重新读取元素，只在完整元素树中唯一匹配时点击一次；未验证成功也不会重按。可提供 `verify_text`/`verify_resource_id` 检查点击前没有、点击后出现的目标，否则 `changed` 仅表示元素树变化。

`android_wait` 的元素树模式支持 `present`、`absent`、`changed`、`stable`，最多 8 次观察。变化等待使用先前结果的 `screen_fingerprint`；稳定只表示连续两次元素树相同，不代表网络加载结束，优先等待具体内容出现。

### 通用视觉工具

以下能力只提供截图、坐标操作和图像变化数据，不识别游戏胜负、不生成策略、不自动重试。纯截图、局部放大、图像等待和操作后截图需要当前 Harness 模型声明图片输入能力，且不能关闭图片输出。默认调用方式保持兼容。

- `android_observe({mode:"screenshot"})`：跳过 UIAutomator，直接截屏。返回 `capture_mode:"screenshot"`、空元素列表、`rotation:null` 和新的观察 ID；不返回元素树指纹。适合游戏和自绘界面。默认 `mode:"ui"` 保留元素树读取。
- `android_observe({mode:"screenshot",region:{x:100,y:200,width:300,height:200},scale:2})`：裁剪原图中的指定区域并按整数 1–4 倍放大。区域不能越界；处理及输出最多 16,777,216 像素，输出单边最多 8192。放大使用最近邻，不增加原始细节。`width/height` 始终是原屏幕尺寸，附件尺寸和映射由 `image_transform` 提供：`原图 x = region.x + 图片 x / scale`，`原图 y = region.y + 图片 y / scale`。点击和滑动必须使用原图坐标。
- `android_wait({condition:"image_changed",region:{x:100,y:200,width:300,height:200},timeout_ms:10000})`：以**本次调用第一张截图**为基准，等待指定区域发生变化。不能用于证明前一次点击造成了变化；要验证点击，应检查操作后截图。省略区域则比较全屏。
- `android_wait({condition:"image_stable",stable_ms:1000,timeout_ms:10000})`：等待画面连续稳定。每次显著变化会重置稳定基准和计时，缓慢累积的变化也会相对基准检测。返回 `met`、`timed_out` 或 `geometry_changed`，以及采样次数、耗时、变化比例、稳定时长和最后可用截图。首次截屏失败仍报错；超时截图的实际时间以 `captured_at` 为准。

图像等待的 `timeout_ms` 范围为 100–60000 ms，从取得设备执行机会开始计时；`interval_ms` 范围为 100–5000 ms，默认 `min(500,timeout_ms)`。`change_ratio` 默认 0.01，表示发生变化的像素占比；`pixel_threshold` 默认 16，表示 RGB 任意通道差值超过该值才算变化像素。变化比例严格大于阈值才满足 changed，小于等于阈值允许继续计时 stable。图像稳定不等于动画、加载或任务完成，含义由 AI 检查截图决定；图像参数不能与元素查找条件、`baseline_fingerprint`、`max_attempts` 混用。

`android_tap`（含长按）、`android_swipe`、`android_gesture`、`android_key`、`android_input_text` 可增加 `return_screenshot:true` 和可选 `screenshot_delay_ms`（0–5000 ms，默认 300）。在同一次串行操作中完成动作、可取消等待和纯截图，返回新的 `observation_id`，可直接用于下一次动作。旧 ID 仍然失效；返回截图不代表操作达到预期。手动输入、任务取消或断连会中断等待。动作已经发送但截图/附件保存失败时保留 `status:"sent"` 并返回 `screenshot_error`，不重放动作，调用方应重新观察。输入文字仍须先用 UI 模式确认输入框焦点。

验证：`node --test tests/visual-tools.test.mjs` 覆盖坐标映射、图像变化、取消、单次操作和 Harness 图片输出。`npm run test:visual-device` 使用已授权手机验证实际截图与工具调用；只发送一次唤醒键，不启动或点击游戏，不调用模型。

跨屏工具先确认唯一的可滚动区域；多个区域时用观察结果的 `scroll_resource_id` 和 `scroll_class_name` 选择。资源 ID 允许空字符串，表示只匹配无资源 ID 的容器。`android_read_list` 需要标题锚点的文字、资源 ID 或类名；首屏所选区域没有标题时不滚动。标题按规范化文字、包名、资源 ID 去重，同名内容可能合并；行结构不明确时只返回标题，不能推测热度、排名等字段。每条结果链接到 `pages` 中的屏幕编号。视觉模型按页收到截图附件，文字模型收到原始行文字。任务记录可打开每屏依据与结构化结果。慢速拖动后停留再抬手，抑制惯性。相邻屏没有重叠标题时返回 `continuity_lost`，保留之前连续可确认的条目，避免数量够了但中间漏项。`unchanged` 或 `no_new_items` 只表示停止条件，不宣称列表已到底。元素树缺失或截断时停止自动翻页，仍可由视觉模型使用现有观察与明确坐标工具操作。

中文搜索流程为：找到搜索入口并点击，重新观察，确认输入框 `editable=true` 且 `focused=true`，调用 `android_input_text`，再查找搜索结果。`replace=true` 会先在当前输入框全选，再粘贴；实际文字和结果仍需重新观察核对。没有可验证焦点的自绘输入框暂不支持原生文字输入工具。

0.6.1 移除“人工接管 / 允许 Agent”按钮及其权限状态。手动点击、按键、输入可直接操作；若正在执行 Agent 手势，先中断该动作并释放旧触点，再执行新的输入。Agent 重新观察后可直接继续。手动拖动期间仅等待触点抬起，避免把两段手势混在一起，不需要任何授权按钮。

关闭侧栏仅移除观看者，设备服务继续运行。主动断开或连接意外中断后，可从面板重连，也可由新工具调用直接建立连接；不需要再允许 Agent。取消、空闲、销毁只清理对应对话的任务与观察，不影响其他对话正在执行的操作；销毁时还会清除其设备绑定。`android_release` 只清理本对话，不锁定或保留手机。

截图与界面文字属于应用内容。文字模型在元素树不可用时应停止并切换视觉模型。受系统保护的屏幕可能无法截图，UIAutomator 也可能无法提供 WebView、游戏或自绘界面的完整元素。

## 手机操作

- 插件加载时打开 Android 面板，面板中只有一台已授权手机时自动连接。
- 左键点击对应手机点击；按住后拖动对应长按、拖动和滑动。鼠标移出画面时仍能正常结束手势。
- 右键返回，滚轮滚动。画面右侧提供返回、主页、最近任务和唤醒按钮。
- 点击画面中的手机输入框后，可用电脑键盘输入英文、数字，使用方向键、退格、Enter 和 Ctrl+A。
- 中文、多行和 emoji 输入使用底部文字框及“输入文字”按钮，通过手机剪贴板粘贴，会替换手机剪贴板内容。
- 失焦、切换应用、画面旋转和断开连接时释放触点，防止持续按压。单次无移动按压最多保持 10 秒。
- 画面旋转后拒绝旧坐标操作，等待新画面后重新操作。

控制协议的成功回复表示输入已写入手机控制通道，实际结果以手机画面为准。出现注入权限错误时保留视频并提示检查手机的 USB 调试安全选项。

## 安装到当前桌面版

当前电脑已安装，原有 Pixels 插件保留。开发目录通过 junction 链接到 desktop profile，原配置备份在 `.build/installation`。同一电脑重复安装可以执行：

```powershell
& 'D:\GoCloud\PixelsAndroid\scripts\install-local.ps1'
```

安装后在 Harness 的 Plugins 页面确认 Android 插件已经启用。重新打开 Harness 后会显示 Android 面板，并连接唯一一台已授权手机；多台设备时从列表选择后点击“连接手机”。也可通过会话头部的 Android 按钮打开面板。

其他电脑使用 `dsh-android-1.9.1.tgz` 安装包。需要兼容的 Harness 0.2.1-rc.2；Windows 与 macOS ADB 及 scrcpy 服务端已内置，不需要安装 Android SDK。手机端需开启 USB 调试并授权。macOS 的真机验收状态见 1.9.0 说明。

标准安装命令：

```powershell
& "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd" plugin --profile desktop add C:\Downloads\dsh-android-1.9.1.tgz
```

包内的 `bin/install-profile.ps1` 支持 `-PackagePath`、`-Profile`、`-DshPath`，优先使用桌面自带 CLI，显示其路径和版本；在修改前备份目标 profile 的清单、lock 与补丁文件，已有插件由 Harness 安装器保留。安装后重启目标 profile。系统 PATH 里的同名全局 CLI 可能是旧版，请确认实际版本匹配。

macOS 使用该 Mac 上与 Harness 配套的 `dsh` CLI 安装；先通过 `dsh --version` 确认版本匹配，下面假设该 CLI 已在 PATH 中，不要为了执行命令另装不匹配的旧版 CLI：

```sh
dsh plugin --profile desktop add "$HOME/Downloads/dsh-android-1.9.1.tgz"
```

安装后重启目标 Harness profile，连接设置保持 `adbPath: auto`。Windows 的 `install-profile.ps1` 不用于 macOS。若将来把插件直接嵌入 Mac `.app`，可执行文件应位于真实文件目录而非 ASAR，并随宿主进行正确的签名、公证和分发验证；当前交付形态仍是 Harness 用户目录中的插件包。

ADB 默认自动发现：显式 `adbPath` 优先，其次是 `DSH_ANDROID_ADB_PATH`（若设置），Windows x64/x86 与 macOS Intel/Apple Silicon 自动模式使用对应包内 ADB。其他系统/架构依次查找 PATH、`ANDROID_SDK_ROOT`、`ANDROID_HOME` 与标准 SDK 路径。已有自定义配置会保留；希望改用内置版本时恢复为 `auto` 并移除环境覆盖。改变路径前必须断开当前连接。`dsh-android-doctor --json` 可独立检查包内 scrcpy、ADB 和 USB 授权，结果中的 `adb.source` 区分内置和外部来源。

任务、模板和设置默认写入 `$DSH_HOME/android`（没有 DSH_HOME 时为用户目录的 `.dsh/android`），与插件安装目录分离。可通过 `dataDir` 或 `DSH_ANDROID_DATA_DIR` 指定路径。迁移自定义任务与设置时复制该目录；截图原件由 Harness 附件服务管理，迁移截图还需迁移原 Harness 附件数据。读取来自其他或上次进程的未结束记录时标记“结果待确认”，不假定任务完成。

包清单固定直接依赖版本，开发安装的完整依赖由 package-lock.json 固定。

当前电脑原 profile 使用 pnpm 10 的 store，桌面自带安装器使用 pnpm 11，直接 add 会报 `ERR_PNPM_UNEXPECTED_STORE`。本机安装脚本只增加 Android 的本地链接和 bundle 配置，保留原有依赖目录与配置。

## 版本与配置

Tango ADB 相关库固定为 3.0.0-beta.4，该版本提供 scrcpy 5.0.1 适配。所有依赖由 package-lock.json 固定。默认最长边 1280、30 FPS 上限、4 Mbps，关闭音频，开启输入控制，保持手机自身电源状态。

Host 配置支持 `adbPath`、`adbPort`、`maxSize`、`maxFps`、`videoBitRate` 和 `connectTimeoutMs`。ADB 自动发现规则见安装说明；连接本机 5037 端口，插件不主动停止共享 ADB server。

0.5.0 配置增加 `dataDir`、`maxCalls`（1–1000）和 `taskTimeoutMs`（100–3600000）。显式 Cordis 插件配置优先于本机保存设置。这里的时限是 Android 任务的整轮时限，每个工具仍有自己的合作式取消期限。

手机切换方向会产生新的编码配置，前端根据编码配置更新画面。面板关闭仅结束观看通道；插件停用或点击“断开”才结束设备连接。解码积压超过上限时停止本次观看连接，并提示重新连接。

## 第三方资源

ADB 来自 [Google 官方 Platform-Tools](https://developer.android.com/tools/releases/platform-tools)，固定版本 37.0.1。Windows 文件位于 `vendor/adb/windows`，macOS Universal 文件位于 `vendor/adb/macos`，附带原始库、`NOTICE.txt` 和 `source.properties`；归档与各文件 SHA-256 记录于 `vendor/runtime-manifest.json`。升级流程见 [vendor/README.md](vendor/README.md)。
