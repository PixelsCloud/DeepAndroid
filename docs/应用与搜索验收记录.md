# 0.4.0 应用与搜索验收记录

日期：2026-10-24。Windows、Harness Desktop 0.2.1-rc.2、USB Redmi K40S / Android 14。

## 功能

- 新增 `android_apps`：从 scrcpy 5.0.1 的 `list_apps` 获取当前手机启动器应用的本地名称、包名与系统标识，支持过滤与分页。真机读取到 130 个可启动应用。
- 扩展 `android_open_app`：支持确切本地名称或明确包名。没有唯一名称匹配时返回候选，未启动应用；兼容原有包名参数。
- 新增 `android_find`：文字/描述可作包含或完全匹配，资源 ID、类名、包名与可编辑条件可组合。最多观察 3 次，观察阶段总期限 45 秒。返回匹配元素、本次观察 ID 和截图；每次观察替换旧观察。
- 增加元素 `focused` 状态。原生文字输入必须在最新观察中确认有聚焦的可编辑框；支持全选后替换文字。
- 聊天工具卡区分“找到”“未找到”“重名未启动”“界面元素不可用”，不把查找失败显示为已发送操作。

应用列表扫描使用随机命名的独立 scrcpy 临时文件，校验本地服务文件 SHA256，结束时只清理自己的文件，不关闭正在使用的镜像服务或共享 ADB。

## 验证

类型检查、构建与 37 项自动化测试通过。新增覆盖本地化与长应用名、重名和未找到、应用分页、字面匹配与条件组合、查找次数边界、接管中断查找、输入框焦点、替换文字，以及旧观察拒绝。

`npm run test:search` 使用真实 Harness ToolRuntime 与真实 USB 手机，未调用模型：

1. 查询“设置”，核对包名 `com.android.settings`，按 `app_name` 启动。
2. 找到“搜索系统设置项”，点击后重新观察，确认 `android:id/input` 为聚焦的 EditText。
3. 粘贴中文“电池”，观察确认输入框内容完全一致；读到“省电与电池”“电池状态”“电池电量”等结果。
4. 用替换模式输入“显示”，确认内容没有追加到原查询后，并找到“显示刷新频率”“显示大小”等结果。
5. 查找不存在的字面目标，恰好观察 2 次后返回 `not_found`，未重复执行输入或点击。
6. 按 Home 并观察到 `com.miui.home`，释放控制。

原始证据：`.build/evidence/search-smoke.json` 与 `search-*.png`，不包含在安装包中。发布前还复测真机接管、取消及模拟断线恢复流程。

## 边界与桌面验收

用户已确认上一版桌面任务、人工接管和取消验收完成。本版桌面聊天搜索任务交给用户测试，可输入：“使用 Android 原生工具打开设置，搜索电池，读取搜索结果，然后返回桌面。”

查找仅针对当前可见元素树，不会自动遍历所有页面；图片模型可以检查截图。每次查找调用受次数和期限约束，整个模型对话仍依赖现有 Harness 循环，未增加第二套 Agent 循环。没有可验证焦点的自绘输入框不执行原生粘贴。应用列表只包含当前枚举到的可启动应用，不代表所有后台包和其他 Android 用户空间。
