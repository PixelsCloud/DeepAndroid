# 0.3.1 恢复机制验收记录

日期：2026-10-24。设备：USB Redmi K40S / Android 14。Harness Desktop：0.2.1-rc.2。

## 修复

1. 取消动作后释放控制权，避免其他对话持续被阻挡。连接建立期间取消调用可立即返回，设备服务继续管理共享连接启动。
2. 接入 Harness 的 `agent/status` 与 `agent/disposed`：任务退出为 idle 时自动释放自己的占用，销毁时清除该对话绑定。
3. 主动断开和传输意外中断后暂停 Agent。必须先连接手机，再点击“允许 Agent”，防止模型下一次调用又自动连上。
4. 新连接清除旧视频缓存；旧观察在连接和控制状态变化后失效。
5. 恢复请求与新接管并发时，以最新接管为准。无连接时禁用“允许 Agent”，面板给出重连与恢复提示。

## 验证结果

类型检查、构建与 28 项自动化测试通过。新增测试覆盖活动动作取消、启动中取消、主动断开、视频流结束、生命周期释放、恢复与接管竞争，以及绑定设备不会自动换为另一台。

`npm run test:recovery` 通过真实 USB 手机、真实 Harness ToolRuntime 和发布的面板 UI 共用同一设备服务，验证：

- 点击实际“人工接管”按钮，中止手机按压，后续动作被拒绝。
- 点击“允许 Agent”后，旧观察仍被拒绝，重新观察可继续。
- 取消动作后另一对话可观察手机。
- Harness 生命周期事件释放占用，销毁清除绑定。
- 关闭并重开面板复用同一视频连接。
- 关闭测试自身的视频传输模拟连接丢失；面板显示异常、Agent 暂停；明确断开、重连并允许后恢复。
- 主动断开后 Agent 工具无法自动重连；明确连接与允许后操作成功，最后确认手机回到 `com.miui.home`。

本轮建立 3 次视频连接，浏览器没有未处理的页面错误。证据：`.build/evidence/recovery-smoke.json`、`recovery-panel.png`。首次测试因等待条件误用了面板卸载前的帧数而未真正重连，已修正为必须存在新画布且已显示帧，再次运行全部通过。

## 用户桌面聊天验收

按用户要求，此轮不代发桌面聊天任务。部署新版后由用户执行：

1. 输入“用 Android 原生工具打开手机设置，查看 Android 版本，然后返回桌面”。确认只需一句话即可完成，右侧画面跟随，结束后显示 Agent 空闲。
2. 执行过程中点击“人工接管”。确认手机动作停止；点击“允许 Agent”后在聊天中让模型继续，模型应重新观察。
3. 执行过程中点击 Harness 的停止按钮。确认任务停止、触点释放，另一对话可使用手机。
4. 主动断开后让模型继续，应该提示先连接和允许。重新连接并允许后恢复。
5. 实体 USB 拔插需另行手动验收；本轮只模拟测试自身视频传输关闭，不重置共享 ADB，不切换系统 USB 配置。

桌面自动点击尝试返回 `coordinate input geometry is unavailable`；随后用户明确选择自行进行 Harness 聊天测试，本轮按该要求完成后端与面板恢复验证。

## 用户反馈

用户已回传桌面 Agent 的完成报告：进入“我的设备”和“全部参数与信息”，读取 Android 14 后返回 `com.miui.home`，控制已释放。随后用户明确确认人工接管和取消验收也已完成，要求继续开发。以上按用户反馈记录通过；实体 USB 拔插不在此确认范围内。
