# 1.8.0 内置运行依赖验收

日期：2026-10-26。目标：Windows 用户安装 Android 插件后，无需自行下载 ADB、scrcpy 服务端或配置 SDK/PATH，即可连接已授权的 USB 手机。

## 交付内容

- `vendor/adb/windows`：Google Platform-Tools 37.0.1 中的 adb.exe、AdbWinApi.dll、AdbWinUsbApi.dll、libwinpthread-1.dll、原始 NOTICE.txt 与 source.properties。
- `vendor/scrcpy-server-v5.0.1`：原有 scrcpy Android 服务端及 Apache-2.0 许可证继续随包分发。
- `vendor/runtime-manifest.json`：固定版本、下载来源、下载归档 SHA-256 与全部必需文件 SHA-256。正常构建和安装不联网下载这些文件。
- 自动模式优先使用插件安装目录内 ADB，保留显式 adbPath 和 DSH_ANDROID_ADB_PATH 高级覆盖。缺失或损坏的内置运行文件明确报错，不静默选用其他版本。
- 构建先核对必需资源；`npm pack` 的 prepack 自动构建并检查资源，防止遗漏二进制或 DLL 的包流出。
- 诊断增加内置 scrcpy 检查；未发现手机时说明数据线、USB 调试授权及 Windows 设备驱动检查方法。

服务端 jar 由 Android 的 app_process 执行；电脑不需要 Java。前端使用 WebCodecs，录制直接写 MKV，电脑不需要 scrcpy.exe、SDL 或 FFmpeg。

## 实际验证

1. `npm run typecheck`、`npm run build` 通过。
2. `npm test`：**227/227 通过**，覆盖原有功能、ADB 选择顺序，以及必需 DLL、可执行文件、清单项、scrcpy 服务端缺失或损坏的拒绝逻辑。
3. `npm pack --pack-destination .build` 生成 `.build/dsh-android-1.8.0.tgz`，约 **6.5 MB**，包括全部运行文件、DLL 与许可证。
4. `node scripts/runtime-package-smoke.mjs --device` 从真正 tgz 解压到带中文和空格的独立目录，以无关目录作为 cwd；子进程清除 SDK、ADB、Java 和 Node 模块路径覆盖，PATH 只保留 Windows System32，LOCALAPPDATA/SDK 指向无 SDK 的测试位置。
5. 从解压后的 dist 导入服务，实际执行的是该包内 adb.exe，版本 **37.0.1-15733141**，来源为 `bundled`。清单中每个必需文件均与打包前字节一致。
6. 通过已授权的 Redmi K40S / Android 14 读取 **130 个应用**，证明包内服务端可由手机 app_process 执行；建立投屏取得 **576×1280、1 份编码配置及 3 帧视频数据**。
7. 在解压的测试副本中移走必需 DLL、破坏 adb.exe，均返回 `BUNDLED_RUNTIME_INVALID`，然后恢复副本。

证据：`.build/tests-180.log`、`.build/pack-180.log`、`.build/evidence/runtime-package-180.json`。ADB 在受限沙箱内遭到 Windows DLL 初始化限制，因此运行二进制的验收在已授权的沙箱外完成；其 SDK/PATH 隔离仍由测试子进程执行。

## 范围与限制

- 实际真机验收平台为 Windows x64；Google ADB 本身为 x86 PE，选择器也支持 Windows x86，但未进行第二套 x86 系统验收。macOS、Linux、Windows ARM64 尚未提供对应内置包，保留外部 ADB 发现。
- 验收复用现有共享 ADB server，未停止或重启该服务；仅读取应用与投屏，不点击手机界面，不调用模型，不发送消息。
- 本次验证了 npm 包内容与包内运行文件的独立定位；JavaScript 依赖由现有测试工作区提供，未声称完成全新 Windows 虚拟机、Harness 全量离线安装或无驱动设备验收。
- 用户仍须安装兼容的 Harness，并完成正常插件依赖安装；手机须开启 USB 调试并授权，部分 Windows 电脑可能需要厂商 USB 驱动。这些不由插件静默修改。
