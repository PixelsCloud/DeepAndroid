# 1.2.0 历史复用与 Android 能力扩展

2026-10-25，在当前 Windows / Harness Desktop 0.2.1-rc.2 / Redmi K40S（Android 14）环境交付。

## 已交付

沿用 Harness 原生工具和现有 Agent 循环，共注册 27 个 Android 工具。新增历史报告搜索与回读、手机目录浏览、双向文件传输、标准单 APK 安装、剪贴板、屏幕电源、旋转和系统面板、画质及音频设置、后台音视频录制。系统按键增加音量、静音、唤醒/休眠及复制/剪切/粘贴。没有增加 MCP 服务或独立模型调用。

手机页仍以画面为主。文件与录像记录在独立“文件”页；右侧“更多”打开设备、剪贴板、画面、录制四类紧凑弹窗。录制期间“更多”按钮显示“录制中”，详细任务卡继续保留在任务页。

历史回读建立当前对话可引用的证据别名，保留原采集时间、设备、报告 ID 和原观察 ID。新报告可以引用这些真实来源，原报告不修改；历史别名不能用于操作手机。缺失截图仍可读取文字，但不能声称已重新看图核实。新增“历史结果对比”模板。

文件单次最大 2 GiB，只处理普通文件；覆盖须明确选择。发送先写随机临时文件再提交，并对照手机和电脑 SHA-256；取回文件在完整传输后提交本机目标。HTTP 只能下载已记录的成功文件，浏览器使用短时、单次票据流式下载；不会把整个大文件读进浏览器内存。任务可取消，重启后旧进行中记录标记为结果未知，不自动重放。暂存上传在完成或服务关闭时清理，遗留超过一天的暂存文件可在服务加载时清理。

画面支持最长边、帧率上限和码率，音频支持设备输出和应用播放两种来源，未请求麦克风。设置保存于独立文件，保存和立即重连应用分开；应用设置会结束当前录制并使旧观察失效。音频为 PCM 48 kHz 双声道，浏览器用 Web Audio，播放需用户手势，可调电脑播放音量；音频失败不关闭视频。

后台将原始 H.264 与可用 PCM 音轨写入 MKV，使用设备时间戳，不依赖运行时 FFmpeg。关闭面板继续录制；默认 10 分钟，工具可设置 1–3600 秒，上限 512 MiB / 16 MiB 写入积压；8 秒无关键帧失败。分辨率改变、旋转或断线结束当前片段，正常片段保留；异常进程退出记录不冒充保存成功。

剪贴板只在明确请求时读取或写入，不隐式同步到电脑；写入不自动粘贴，不在任务记录保存正文。针对 SDK 与 scrcpy 的差异，安装客户端剪贴板回复解析器，同时关闭服务端自动同步，以便显式 GetClipboard 能收到回复。Android 没有回复时提示内容可能为空或受系统限制。

## 验证

- 类型检查、构建、130 项自动测试通过。新增 14 项覆盖历史跨对话引用与原报告不变、缺失图片与删除、真实运行时拒绝历史点击、路径引用与中断上传、参数持久化、原生安装失败呈现、音频失败隔离、MKV 起始关键帧与轨道、并发启动及旋转结束片段、HTTP 鉴权与下载边界。
- 真实 USB + Harness ToolRuntime：2 MiB 随机二进制文件，经中文、空格、引号和 `$ &` 文件路径往返，手机与电脑 SHA-256 一致，下载逐字节一致；同名覆盖拒绝正常。剪贴板写入、回读并恢复；音量增减与系统面板指令发送正常。
- 屏幕电源：SurfaceFlinger 从 `powerMode=On` 变为 `Off`，期间截图仍可取得，再恢复 `On`。旋转指令得到服务端确认；本次桌面应用保持竖屏，未把指令确认当作横屏成功。系统传感器与当前应用可限制或立即恢复方向。
- 音频与录制：1440/1600 等最长边参数通过重连生效；一次 720×1600 H.264 + PCM MKV 约 9.7 秒、2.1 MiB，收到 660 个音频包，其中 188 个包含非零采样。使用独立短时 shell 音调测试进程验证真实非静音采集，不依赖安装测试 APK；临时 dex/jar 随后清理。ffprobe 识别 H.264 与 48 kHz 双声道 PCM，FFmpeg 完整解码无报错。
- Chromium UI：选择文件 → 上传暂存 → 发送 → 浏览目录 → 取回 → 浏览器下载，字节与文件名一致；单次下载票据不可重放。画质单独保存后，活动连接仍用旧参数；立即应用后，视频重新解码并接通音频。录制在关闭弹窗后继续，按钮显示录制状态，停止后成功下载 MKV。更多操作在 360/480 px 下无横向溢出；手机页在 360/480/860 px 下的右侧顶端按钮与画面布局回归通过。
- 安装包在独立 profile `android-120-final`（实际路径位于 C:，不链接开发目录）安装验证；安装后 Host/UI 与最终构建逐字节一致。完整 Harness 界面启动恢复、结果页恢复、关闭自动展开后的手动开启正常；5 个内置模板可用。

测试使用真实 USB、SDK 工具注册器、实际浏览器和本机文件。模型能力信息仅为测试夹具，没有发送聊天或调用付费模型；自然语言意图理解与 Agent 对比内容质量留给用户在 Harness 聊天验收。

## APK 当前限制

已接入标准 `adb install --no-incremental -r`，单 APK 正常安装、替换保留数据，不降级、不批量授权、不启动应用，也不绕过手机审批。测试 APK 安装被手机返回 `INSTALL_FAILED_USER_RESTRICTED: Install canceled by user` 拒绝，工具、卡片及文件记录保留失败原因。已请用户开启手机的 USB 安装并允许提示，尚未得到开启后的反馈，所以**没有宣称真机成功安装通过**。手机限制解除后再用同一个原生安装工具补验。拆分 APK / XAPK 不支持。

## Agent 工具入口补验

针对“让 Agent 直接控制手机”的交付要求，另从 `dsh-android/agent` 独立入口加载插件，不提供 WebServer、不启动浏览器、不挂载任何面板。通过 Harness 的实际 systemPrompt 工具提供接口验证，27 个 `android_*` 都进入模型可见清单。新增自动测试后，全部 131 项通过。

真实 USB 上，全部经 ToolRuntime 调度完成：发现与绑定手机 → 电脑文件发送 → 列目录确认 → 取回并逐字节比对 → 开始录制 → 打开设置并观察确认 → Home 并观察桌面 → 停止录制取得真实本机路径 → release。没有使用任何按钮或面板 HTTP 接口，没有替用户发送聊天或调用付费模型。证据为 `.build/evidence/agent-only-smoke.json` 与 `.build/tests-agent-tools.log`；该补验只增加测试与说明，当前已安装的 27 项原生工具实现不变。
