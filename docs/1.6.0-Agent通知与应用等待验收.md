# 1.6.0 Agent 通知与应用等待验收

交付日期：2026-10-26。环境：Windows、DeepSeek Harness Desktop 0.2.1-rc.2、Redmi K40S / Android 14、USB ADB。

## 交付范围

新增三个模型可见的原生工具，总计 44 个。使用 Harness 自身工具运行时，Host 和无面板 `dsh-android/agent` 提供相同能力；没有增加面板按钮、独立 MCP 服务或模型调用。

| 工具 | 实际行为 |
| --- | --- |
| android_notifications | 读取当前用户及 USER_ALL 的活动通知，按确切包名、实际通知键、字面关键词筛选。返回可读标题、正文、长正文、诊断时间、持续标记和内容指纹。默认扫描 20 条、最多 50 条，返回继续扫描的 offset。未知、隐藏、截断、撤回或不支持的内容与真实空结果分开返回；关键词筛选后仍保留本次所有扫描记录的不可读计数。 |
| android_wait_notification | 默认先建立最多 200 条同范围通知的指纹基线，等待新通知或同键内容/更新时间变化。new_only=false 可匹配已有通知。也可传操作前查询所得的完整 baseline_fingerprints 与 baseline_user_id，立即比较当前状态，避免漏掉快速完成的任务。基线用户不符、初始详情不完整或范围过大则返回不可用。 |
| android_wait_app | 等待当前用户确切包名与可选活动稳定 resumed，默认要求当前焦点窗口属于该包，锁屏显示时不匹配。相对类、完整类和同包组件统一规范化，优先使用 topResumedActivity，多显示器不唯一或用户不符时不猜测。每次活动变化会重置稳定期。 |

通知读取使用系统已有 `cmd notification list/get`，不读取通知历史、不安装 APK、不授予监听权限、不变更 DND、不点击或撤销通知。Android 14 的命令行为可对照 [官方 NotificationShellCmd 实现](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android14-release/services/core/java/com/android/server/notification/NotificationShellCmd.java)。键的用户/包名前缀先用于过滤，末尾标签和分组后缀保持不透明，兼容自动分组摘要。

文本按通知诊断结构读取，身份必须与本次实际活动键相符，歧义/重复字段保持未知。类似 `Error:` 的应用正文作为数据读取，不套用通用 shell 的报错判断。文字是应用提供的数据，不是可信指令或独立完成证明；可读字段各最多 2000 字。when_ms 由应用指定，与系统诊断创建/更新时间分开。内容指纹忽略展示时间等易变诊断字段，避免仅因通知被显示就误判更新。

等待默认 30 秒、最多 120 秒，轮询 500–5000 ms；应用默认稳定 500 ms，范围 0–10000 ms。独立计时器保留并在结束时清理；每次诊断读取也与取消信号竞速，底层未及时结束时不会无限延长等待。取消、会话结束、断开会终止新工具的查询/轮询，只关闭自身 ADB 客户端，不重启共享 ADB server。查询不建立视频连接或保留手机操作权，手动操作和其他任务仍可继续。

通知匹配返回 completion_confirmed=false，活动匹配返回 content_ready_confirmed=false。通知不是文件完整、消息送达或业务成功的证明，活动/焦点也不证明内容已加载；后续应查询实际文件、核对哈希或重新观察。轮询可能漏掉采样之间出现并撤回的短暂通知，读取不到的文字无法匹配关键词。初次基线之前已出现的通知默认被排除；快速任务应使用操作前的实际完整基线，或者明确允许已有匹配并自行核对时间和内容。

本机任务记录只保存通知关键词和通知键的长度，不复制正文或完整筛选词；Harness 对话中的工具结果仍按 Harness 自身规则记录。

## 自动验证

类型检查、构建、198 项自动测试全部通过，相比 1.5.0 新增 24 项，覆盖：

- 不透明通知键及分组后缀、多行/字面文字、易变诊断不影响指纹、内容更新改变指纹、隐藏与重复字段不猜测、身份不符拒绝。
- 当前用户与包名在正文读取前筛选、关键词按字面匹配、接口不可用与真实空结果区分、用户切换丢弃数据、通知撤回保留不完整状态、分页未扫完和隐藏文字不冒充无匹配。
- 旧基线排除、同键更新、操作前基线立即识别快速结果、基线字段和用户检查、超时、取消、传输错误传播、不完整基线拒绝。
- 前台优先级、用户隔离、活动规范化、多显示器歧义、焦点与锁屏约束、活动变化重置稳定期、未知状态保留。
- 不建立视频、会话结束和断开取消、输入边界、筛选词日志省略、真实 Harness 工具注册及三项调用。
- 两种等待在底层读取收到取消后仍不结束时，仍于约 500 ms 返回 timed_out，不被底层挂起拖延。
