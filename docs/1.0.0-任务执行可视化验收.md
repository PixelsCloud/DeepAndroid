# 1.0.0 任务执行可视化

手机、结果、调试三个页面共享任务卡，显示实际操作状态、最近一步、耗时、调用次数和列表条数。卡片可选择最近 20 项手机任务；详细任务记录仍保留在调试页。操作之间显示等待 Harness 下一步，不显示估算完成百分比。“执行已结束”与报告内容是否完整分别展示。

停止入口使用已安装 Harness 原生 `Agent.cancel({kind:'hook',reason})`，同步取消所选任务的操作信号并清理该对话的观察和待执行动作，不断开视频或停止其他对话。按任务 ID 校验；重复请求幂等，过期请求不会取消新任务。取消在 Agent idle 前显示正在停止，结束后保留摘要。没有可用原生回调的历史记录不能伪装为可停止。

`android_read_list` 每完成一个可确认的连续页面，保存计数、原始条目和截图引用。读取被停止或失败时，将已有条目保存为部分完成的原始结果；不记录尚未确认连续性的页面，也不自动重试输入。正常结果继续使用原来的保存逻辑，已保存的截图引用在最终工具输出中复用。晚到的工具结果仍写回原任务，避免 Agent idle 后生成虚假新任务。

任务卡提供结果直达与最近截图查看。结果直达会清空不相关筛选，并定位结果所在页。已删除报告不会继续出现在任务卡链接或继续草稿中。截图明确标为最近一次已保存观察，不代表当前实时状态。

继续草稿包含原应用、最近一次列表目标与计数、停止原因和已有结果片段，要求重新观察并保留原报告另存新报告。数据用 JSON 引用，明示设备内容不是指令；大报告截断时标出缺失行数。用户在原对话检查并发送，插件不会代发聊天或启动第二套模型循环。

## 已验证

- 类型检查、构建及 101 项自动测试通过，新增 6 项覆盖思考阶段停止、其他对话隔离、幂等及过期停止、没有原生取消回调、晚到结果归属、旧记录非活动状态、草稿与删除语义、接口来源限制，以及实际 Harness ToolRuntime 调度中取消后保存部分结果。
- 真机设置列表：读取中停止，保留 10 条和截图，画面采集连接时间保持不变；查看截图、复制草稿、打开对应部分结果；重新观察后读取 20 条并保存整理结果，最后回桌面。
- 真机知乎热榜：同一流程中停止后保留 6 条，随后重新观察并完成 20 条标题读取及保存，最后回桌面。这里只保存直接读到的标题；没有推断未暴露的排名或热度。
- 360 / 860 像素面板无页面横向溢出，运行状态、停止状态、截图弹窗和草稿完成视觉检查。
- 界面延迟测试：旧轮询尚未返回时切换任务再停止，立即作用于选中的任务；旧响应不能恢复已停止状态或覆盖用户选中项。在另一个结果筛选下，任务链接仍能定位第二页的准确旧报告；删除后链接消失。
- 原有结果管理与启动恢复回归通过；包括重命名、搜索日期分页、删除恢复、延迟搜索响应、后端换端口恢复断开选择、断流重连上限，以及缺失手机时不误连其他设备。

真机脚本使用实际原生工具注册器与手机面板，取消的 Agent 回调由测试对象提供；没有调用付费模型或替用户发送聊天。真实模型的规划、最终回复以及用户在原对话发送草稿后的行为，留给 Harness 聊天验收。

证据：`.build/evidence/task-flow-smoke.json`、`task-flow-zhihu-smoke.json`、`task-ui-smoke.json`、`tasks-running.png`、`tasks-stopped-360.png`、`tasks-continuation.png`、`unit-100.txt`。测试数据均使用 `.build/tests` 隔离目录，不修改用户已有报告。
