# 1.1.0 详情与正文阅读

新增原生工具 `android_read_page`，共 17 个 Android 工具，沿用 Harness 当前 Agent 与图片能力。手机页保持画面与操作区，阅读进度、报告与截图留在任务和结果页。

文字模式明确选择正文元素与唯一滚动区域，按向下顺序读取当前视图开始的范围。只合并相邻页面有序、发生位置移动的重叠文字；保留文章后面实际重复的段落，避免全局去重丢内容。支持完整片段重叠和长片段的字符重叠。区域之外的浮动工具栏不参与读取。标题不匹配、界面截断、区域不唯一、上下文改变、衔接无法确认或达到上限时明确停止。暴露出的文字是原始界面片段，不是自动语义提取或完整文章判断。

截图模式 `mode: screenshots` 用于文字未暴露或需要识图的页面，只允许当前模型已声明图片输入能力且未关闭图片附件时使用。收集原始手机截图与已选择区域的边界，直接交给当前 Harness 模型阅读；插件不执行 OCR，不另起模型。图片哈希相同或达到屏数上限不证明文章已到底，截图模式不声称文字已读或连续性已确认。缺少唯一滚动区域时不盲目滑动，仍返回实际观察供判断。

两种模式每次最多 7 次滚动、8 屏。文字默认 60 个片段、12000 字，最多 100 个片段、24000 字；这些是上限，不是文章预期长度。元素文字保留已有截断边界，并新增可判断的截断及裁切标记；隐藏节点及其后代不参与解析。

逐屏保存任务进度与截图引用。原始文字或仅含图片的阅读结果都保存为部分完成，取消后保留已确认的片段或图片。摘要、关键观点与完整性判断由现有 Agent 结合实际内容调用 `android_save_result` 保存。没有表格行的截图报告按依据张数显示。继续草稿带入摘要依据标识；首次失败没有进度时明确为未知正文进度，不编造列表数量。

内置“列表详情阅读”模板默认知乎热榜前三条：先保存列表标题，逐项进入详情、观察正文与滚动区域、有限阅读或截图核对，返回后重新查找原标题，再进入下一项，最后保存一份带来源的报告并回桌面。问题介绍、回答节选和回答正文需要分别识别；进一步进入回答后，返回列表也需逐层确认。

## 验证结果

- 类型检查、构建及 116 项自动测试通过。新增 15 项覆盖段落顺序及真实重复保留、字符重叠、静止锚点及连续性丢失、重复画面、错误标题与多滚动区、字符/片段/节点截断、静态页面、区域外工具栏、取消检查点、实际原生工具的附件复用与部分结果、截图模式图片能力检查及取消保留。
- 知乎前三条问题详情：逐项进入并返回后重新定位标题。第一条读取 11 个文字片段、471 字，连续性无法确认后停止；第二、三条的题头未能与列表原文通过元素文字核对，分别保存 4 屏原始截图；文字缺失或格式差异都需要进一步看图确认，不能仅凭匹配失败断言页面错误。已视觉核对截图中的标题与列表目标一致。合并报告明确保留空白字段和未读完整原因，未将图片推断成提取文字。
- 三条第一篇回答：从最新观察中的实际回答节选元素进入，明确选择观察到的 `custom_recycler_view` 滚动区域；各读取 4 屏，分别取得 29 / 26 / 46 个界面文字片段、802 / 708 / 507 字。每条逐层返回问题及列表，再重新定位列表标题，最后回桌面。范围均因设定滚动上限停止，未宣称完成全文。
- 任务与结果界面检查：生成三行来源报告、查看截图、窄面板无横向溢出。带历史任务的手机页仍只显示画面和操作；任务切换、延迟响应、停止目标、草稿和旧报告定位回归通过。

真机脚本使用真实 USB 手机、Harness 原生工具注册器和实际界面，保存原始片段或截图；没有调用付费模型或替用户发送聊天。因此当前模型的摘要质量、关键观点整理和自主多层导航仍由用户在 Harness 原对话验收。

证据：`.build/evidence/unit-110.txt`、`detail-reading-smoke.json`、`answer-reading-smoke.json`、`detail-reading-results.png`、`detail-reading-evidence.png`、`task-ui-smoke.json`。测试报告及图片使用 `.build/tests` 隔离目录，不写入用户报告目录。
