# 1.7.1 文件管理器审查修复验收

日期：2026-10-26。修复 1.7.0 审查确认的五个缺陷，保留现有 UI 和 44 项原生 Agent 工具。

## 修复及回归

| 审查问题 | 实际修复 | 验证 |
| --- | --- | --- |
| P1 重试丢失源版本约束 | 新作业保留原 `expected_version`，不继承旧覆盖授权。源变更后仍拒绝，需刷新并重新选择；原源未变时确认后的重试仍可成功 | delete/copy/move/rename/pull/install 六种操作的变化后重试全部拒绝，未调用底层传输或修改；原源未变的失败删除重试成功 |
| P1 覆盖复制提交前未复核目标 | 在共用提交函数中检查 `expected_destination_version`，复制、移动、上传提交使用同一复核路径；保留开始前检查 | 在 cp 期间注入目标修改或删除，均拒绝执行最终 mv；目标未变化时正常完成；上传提交也会拒绝变化目标 |
| P2 长名称无法下载 | 默认缓存使用 UUID 与短扩展名；上传暂存也限制扩展名长度。下载临时文件使用同目录固定长度名称；浏览器名称由原手机路径单独生成 | 本地长名称真实写入，APK 后缀保留，显式本机目标保持；240 字节且扩展名很长的上传暂存成功；HTTP 校验 UTF-8 原名与确切下载字节；真机长名称上传及浏览器下载完整往返 |
| P2 老冲突从最新 100 项列表消失 | 所有 queued/running/conflict 作业优先保留，另附最近 100 项已结束历史 | 老冲突之后再完成 101 个新作业，冲突仍列出且可取消，历史部分仍受 100 项上限约束 |
| P2 重启按 UUID 枚举截取导致最新历史遗漏 | 读取有效记录后按任务时间选择最近 1000 条已结束历史；较早的未结束作业单独恢复为中断，保持结果不确定性 | 1000 项以上、最新时间对应最小 UUID 时仍正确恢复；更早的 running/conflict 也被标为 interrupted；不调用底层修改，不自动重放 |

版本核对仍采用文件类型、大小、修改时间，不能识别保留这些字段的全部外部改写，也不是原子的文件系统比较交换。此次补上复制/校验之后的提交边界复核，不宣称共享存储是静态内容快照。
