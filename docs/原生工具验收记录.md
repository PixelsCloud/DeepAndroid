# 原生工具 0.3.0 验收记录

验收日期：2026-10-24。环境：Windows、DeepSeek Harness Desktop 0.2.1-rc.2、USB Redmi K40S（22021211RC）、Android 14。

## 实现

已注册 `android_devices`、`android_bind`、`android_observe`、`android_tap`、`android_swipe`、`android_input_text`、`android_key`、`android_open_app`、`android_release`。使用 Harness 原生工具、附件与模型能力服务，复用现有 Agent 循环。

设备服务独立于面板观看连接。观察包含原始截图尺寸、界面元素及一次性标识；屏幕旋转、人工操作、取消与控制状态变化使旧观察失效。会话之间互斥控制。人工接管中止当前动作、释放触点并拒绝后续动作，人工允许后需重新观察。

## 自动化与真机

- TypeScript 类型检查、构建与 20 项测试通过。
- 使用真实 Harness ToolRuntime 验证参数校验、图片附件投影、文字模型分流与缺失 Agent 上下文拒绝。
- 使用真机和真实工具调度链进入设置，按观察元素点击“我的设备”，滑动找到“全部参数与信息”，读取 Android 14，按 Home 后观察到 `com.miui.home`，最后释放控制。接管后发起点击被拒绝。
- Chrome 实际 WebCodecs 解码及断开重连 3 轮通过，576×1280、硬件解码；本轮首帧观测 940、912、895 ms，仅作为本次样本。
- 当前 Desktop 正常重启后，健康接口确认 9 个 Android 原生工具已注册、1 个面板观看连接、视频持续传输。

## 真实模型闭环

通过桌面安装包提供的 Harness headless Agent 运行真实 DeepSeek 模型 `deepseek-official / deepseek-flash`。工具查询表明该模型声明图片输入能力，观察结果按 Harness 附件格式提供截图。

模型共完成 13 次原生工具调用：设备列表、绑定、启动设置、观察、点击我的设备、观察、滑动、观察、点击全部参数、观察、Home、观察、释放。所有调用成功。每次点击或滑动都使用最新观察，动作后重新观察。最终读出 Android 14、安全更新 2025-03-01，观察确认返回手机桌面并释放控制。

命令行最初未能解析已有凭据；验收脚本仅在子进程环境中复用本机已存储的 DeepSeek API Key，未改写用户凭据或模型配置。此闭环使用独立 headless 进程；当前 Desktop 的加载与共享设备状态另行验证，未通过桌面聊天框自动提交任务。

## 证据与边界

原始证据位于 `.build/evidence`，不包含在安装包：`native-device.json`、`native-model-task.jsonl`、`native-model-summary.json`、`desktop-native-health.json`、`browser-smoke.json`，以及本地截图。headless 事件流会截断较长工具结果预览，完整原生会话另由 Harness 持久化。

当前自动化桌面辅助程序在重启后返回 `foreground window did not report a process id`，因此桌面按钮点击未自动复测。新版控制服务的暂停、恢复与释放机制已由自动化测试和真机工具验证。

本轮尝试重建浏览器人工控制测试夹具时，ADB reverse 与启动夹具页面的命令被自动审批拒绝，返回 `blocked by policy`，未绕过；0.2.0 的 102 次真机人工控制记录保留为历史证据，本轮不重复宣称通过该组完整测试。

当前已覆盖真机核心闭环；多设备实际同时插入、手机拔插故障、长期运行、各品牌输入法、游戏与自绘界面，以及更广泛任务成功率需后续扩展验收。系统受保护页面可能无法截图，UIAutomator 元素树可能不完整。
