## 页面流程

进入“文件”页 → 选择手机 → 进入可读取目录 → 选择或拖入文件 → 执行操作 → 在可折叠作业区查看实际结果。

复制/移动：选择文件 → 目录选择器中前往目标 → 必要时修改目标名称 → 选择此目录 → 作业完成后核对目标。删除：选择项目 → 确认对话框核对设备、完整路径、数量 → 明确删除。取消对话框不创建删除作业。

同名冲突默认暂停该作业；可跳过、修改目标名称后继续，或明确覆盖普通文件。不合并/覆盖已有目录。确认后目标若已变化会再次要求处理或返回错误。源文件若与选择时版本不同则拒绝使用旧选择。其他已接收作业仍可继续。

选择版本由类型、大小与修改时间组成，用于发现可观察的元数据变化，并非内容原子快照；同大小且保留修改时间的外部改写不保证被选择版本发现。传输和普通文件复制继续使用实际哈希核对，变化中的文件或目录仍应先由生产应用停止写入。

作业固定创建时的设备、源路径、目标路径和源版本；切换手机或目录不会改写已接收任务的目标。服务器已接收的传输刷新页面后仍继续；尚未暂存的电脑 File 对象不能跨页面保存，离开前提示，之后需要重新选择。

## 实现与数据

- `src/file-manager-model.ts`：浏览器/Host 共用的路径、名称、目录分页和作业类型。
- `src/file-manager.ts`：目录读取、作业调度、冲突、取消、重试、恢复和偏好；使用已有 `FileService` / `RemoteFiles`。
- `src/browser-file-manager.ts`：页面状态、选择、导航、上传队列和作业显示；API、布局、对话框分别独立维护。
- `src/host.ts`：同源且要求客户端头的 `/x-android/file-manager/*` 接口；读请求随客户端关闭而取消。作业写入后才返回接收结果。
- 作业和位置保存在插件数据目录 `files/manager`，与安装目录分离。旧传输与录制文件仍能在作业区保存。

服务一次执行一个管理作业，最多 100 项等待/执行/冲突作业，并发提交在落盘前预留容量。冲突会保留暂存源；完成、失败、取消或跳过后清理自有暂存文件。未完成记录在重启时标记中断，不自动重放。

查询每页 200 项，最多扫描 10000 项，返回读取数、匹配数、下一页和截断标识；筛选只覆盖读取到的当前目录，分页不是原子快照。目录复制/删除沿用最多 1000 项、32 层、累计 2 GiB 的限制，单文件上限 2 GiB，新名称上限 240 UTF-8 字节。长名称上传使用固定长度的同目录临时名，避免附加后缀超出 Android 单个名称长度。

普通上传/下载核对实际 SHA-256。按需详情哈希在前后元数据变化时拒绝宣称稳定。ADB 传输没有可靠逐字节回调，因此显示传输、提交、核对等实际阶段；仅电脑到 Harness 的 XHR 使用实际上传百分比。文件大小不冒充已传字节数。

手机文件名始终作为文字和独立参数处理，不解释 HTML、通配符或 shell 片段。写操作沿用共享存储/具体子路径保护、正常 ADB 权限和原生操作串行边界；不重启共享 ADB server，不使用 root 或辅助权限。

取消不保证回滚；已进入修改阶段的失败也可能已改变手机文件，显示结果待核对。非上传作业在这种状态下重试需要明确确认。上传重试重新暂存源文件，仍默认不覆盖已有目标。

## 验证结果

`npm run typecheck`、`npm run build` 通过。`npm test`：**216 / 216 通过**，包括原有 198 项及 18 项文件管理服务/接口测试。覆盖根路径与本机路径拒绝、分页排序与过滤、10000 项有界流读取、厂商权限拒绝、源/目标变化、冲突处理、暂存生命周期、并发容量、取消/重试、断线不确定性、哈希不一致、持久化恢复、同源请求限制等。

`npm run test:file-manager`：**14 项 USB 真机端到端检查通过**，使用完整插件 UI 和独立 Chrome：

1. 多文件上传与中文、单引号、美元符、与号名称的真实哈希核对。
2. 文件详情按需哈希、单文件下载的实际文件名及字节校验。
3. 批量下载两个独立文件，校验各自内容。
4. 拖放 File 对象上传，手机哈希一致。
5. 长 UTF-8 名称上传，临时名称不超长。
6. 目录选择器、复制、改名、移动、递归目录复制，核对源已移除及目标哈希。
7. 同名改名保留、明确覆盖、跳过，核对未授权覆盖未发生。
8. 隐藏文件和当前目录字面筛选。
9. 批量删除显示精确路径及数量，取消无副作用，确认后仅删除选中测试文件。
10. 真正 205 项目录加载两页，无重复，前进/后退/上一级可用。
11. `/data/system` 权限拒绝明确显示错误，不伪装为空目录，停用目标上传。
12. 64 MiB 实际传输中取消，显示不确定结果；保留源重试，新作业在页面刷新后继续完成。
13. 恢复“文件”标签、设备目录、排序、隐藏文件偏好和已接收作业记录。
14. 360/480/840 px 无页面横向溢出，作业区可折叠，详情框有界，切回手机仍有解码画面。

`npm run test:file-manager-browser`：**8 项浏览器检查通过**。使用显式 HTTP 测试数据验证双设备选择、旧设备延迟响应隔离、目录选择器延迟响应不覆盖用户输入、拖放字节与设备/目标固定、刷新期间的选择保持与全选/清空、HTML 外观名称无法注入 DOM、APK 确认/系统拒绝显示、断开后的错误状态。

双设备、断线和 APK 拒绝展示使用故障注入，不能计为第二台真机、实体 USB 拔插或成功安装验收。当前手机此前实际标准安装返回 `INSTALL_FAILED_USER_RESTRICTED`；保留此限制，不绕过系统审批，不把发起安装报告为安装成功。

`node scripts/more-ui-smoke.mjs`：360/480 px 的设备/剪贴板/画面/录制面板通过；保存参数与立即重连分开生效，音频恢复；关闭对话框仍录制，停止后 MKV 保存并按实际字节下载。`npm run test:files-ui` 依次运行新文件管理器和这些原有功能回归。

测试只操作自有 `/sdcard/Download/dsh-file-manager-<UUID>` 目录及生成文件，结束后按确切目录清理。权限测试只读；无付费模型调用、无外部上传、无用户文件删除或共享 ADB 重启。截图和结构化结果在 `.build/evidence/file-manager-*.png`、`file-manager-smoke.json`、`file-manager-browser-smoke.json`、`more-ui-smoke.json`。
